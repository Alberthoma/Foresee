# Informe de Actualización — V F2 0017
**Fecha:** 2026-07-26

## Solicitud del usuario
Tras publicar V F2 0016, el usuario reportó que el espacio entre el tab-bar y la barra de acciones (Registros) seguía viéndose muy grande. Pidió reducirlo para que quedaran más pegados.

## Análisis previo al cambio
- Primer intento (revertido): se probó reducir `--tab-bar-mobile-h` (que fija tanto la altura real del tab-bar como el `padding-top` del `body` que le reserva espacio) de `5.5rem` a `4.75rem`. El usuario confirmó que esto cortaba las pestañas con etiqueta de 2 líneas (ej. "Gastos<br/>Recurrentes") en la parte inferior — revertido de inmediato a `5.5rem`.
- Investigación más a fondo: el espacio real no dependía solo de la altura del tab-bar. `#content-area` vive dentro de `<main id="main-wrapper">`, que tiene su propio `padding: var(--space-md)` (1rem) en las 4 direcciones — un espacio adicional, independiente del hueco que reserva `body` para el tab-bar fijo, y que sí se podía reducir sin tocar el tab-bar ni arriesgar corte de íconos/etiquetas.
- Se instaló Playwright + Chromium (en la carpeta de scratchpad de la sesión, no en el repo del proyecto) para comparar con capturas reales a 390px de viewport antes y después del cambio, y confirmar que no había desborde horizontal (`scrollWidth === clientWidth`).

## Modificaciones realizadas

### 1. `css/base.css` — INSERCIÓN
`#main-wrapper` gana `padding-top: var(--space-xs)` (0.25rem), como excepción puntual al `padding: var(--space-md)` general (que se mantiene para los otros 3 lados). Reduce el espacio entre el tab-bar y el contenido sin tocar la altura del tab-bar.

## Verificación
- Capturas Playwright a 390px de viewport, sección Registros: se confirmó visualmente que el espacio se redujo y que las pestañas del tab-bar no se cortan (a diferencia del primer intento).
- `scrollWidth === clientWidth` (390 = 390) tras el cambio — sin desborde horizontal.
- Solo se tocó CSS — bump de `CACHE_NAME` (v17→v18) en `sw.js`.

## Estado final
Publicado como V F2 0017. Confirmado por el usuario que el espacio quedó bien ("quedó bien ahora sí se solucionó").

## Nota aparte (sin cambios de código en esta versión)
El usuario dio una regla de estilo para el CSS de este proyecto de acá en adelante: **no usar variables CSS para espaciado ni tamaños de fuente** (`--space-*`, `--font-*`) — escribir el valor en px directo. Las variables quedan reservadas solo para colores/tokens de tema. Se guardó como memoria de feedback para futuras sesiones. El usuario también pidió dejar anotado que más adelante quiere un refactor completo de `base.css`/`secciones.css` para convertir todas las variables de espaciado/fuente existentes a px literales — no se ejecuta en esta versión, queda pendiente para cuando el usuario lo pida.
